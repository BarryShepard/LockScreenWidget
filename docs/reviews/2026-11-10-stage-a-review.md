# Whole-branch review: native editor, Stage A

Reviewed `258dbbf57c6c703897db7dab2bb7ef91b76f1104..ab592744553d878ce42bf0323a6dd676bd29dc66` against the bounded Stage A plan. Verdict: **changes requested**. The following six findings are independent of the pending secure-lock smoke test.

1. **P1 — Position the panel on the display actually matched by UUID.** `Sources/Views/OverlayPanel.swift:8` passes `CountdownView.overlayFrame(in: screen.frame)`, which is the *global* screen frame unchanged, to an initializer with an explicit screen. [Apple’s initializer contract](https://developer.apple.com/documentation/appkit/nswindow/init%28contentrect%3Astylemask%3Abacking%3Adefer%3Ascreen%3A%29) makes the origin relative to the supplied display. A 1440-point-wide target starting at x=1440 is thus initially placed at x=2880. `Sources/Controllers/LockScreenController.swift:220` then takes the frame from *panel.screen*, i.e. the display where the misplaced window landed, if any. With a third display to the right this can display a personal composition on that display; without one, the window can be left offscreen. The UUID index test cannot catch this. Construct the window with a screen-local rect (or use global coordinates without the screen parameter); use the matched screen as the source of the final frame. Exercise a non-zero origin including left/above layouts without substituting a live secure-lock test.

2. **P2 — Reject truncated source bytes before replacing good image content.** `Sources/SceneTransfer.swift:70` and `Sources/SceneStore.swift:89` treat `NSImage.isValid` plus positive dimensions as validation of the entire file. A headless probe on this host generated an opaque 128×64 PNG (29,128 bytes) and supplied just its first 256 bytes. AppKit reported `isValid == true` and the correct dimensions; decoding returned a transparent final-row pixel where the complete PNG had an opaque colored pixel. The import can therefore return success, assign a new asset and save a visibly broken replacement. The same probe found that merely requesting an ImageIO decode and checking the source's final status also reported success, so verify the actual malformed fixture when choosing the check. Put the validation in one shared import boundary; add failed-replacement and failed-mixed-batch cases using a recognizable but incomplete source. The existing three-arbitrary-bytes test only exercises an unrecognized format.

3. **P2 — Holding Shift before dragging a selected layer prevents movement.** `Sources/SceneCanvasView.swift:128` toggles the selected layer *off* at mouse-down, before a click can be distinguished from a drag. At line 140, `mouseDragged` then rejects that layer because it is no longer in the selection. A previously selected layer (or member of a selected group) cannot be moved along an axis with Shift already down; it simply gets deselected. Pressing Shift after starting the drag is a different input sequence. Defer removal of an already-selected member until a click is confirmed. Check both Shift-click removal and a Shift-held group drag, including one-step Undo.

4. **P2 — Text reported as saved can be stale on the lock panel.** `Sources/SceneEditorWindowController.swift:104` schedules `saveIfNeeded()` on typing. It writes the new text and reports “Сохранено на этом Mac,” but only `commit()` at line 109 forwards a snapshot to the lock controller. If the system is locked while the text editor is still active after that debounce, the lock notification/poll path has no call to flush the editor or read the saved scene. It will use the previous text, or the countdown on the first edit, until editing ends. The eight-second panel-test path explicitly flushes and masks this gap. Forward the debounced snapshot or explicitly synchronize on transition to locked state, without registering another Undo or treating marked input as a finalized edit. Check the store and lock consumer agree while the text editor remains active; this test need not lock the Mac.

5. **P2 — A discarded first text edit permanently disables the countdown fallback.** `Sources/SceneCanvasView.swift:239` calls `onRestoreTypedScene` for a typed edit that ends with the initial scene. On a fresh profile, create a text layer, enter one character, delete it, then Escape. The empty new layer is discarded and history correctly shows no change. Nevertheless `Sources/SceneEditorWindowController.swift:32` calls `commit()`, publishing and writing an empty scene even if the 450 ms debounce never fired. On this launch and all subsequent launches the legacy fallback is gone. Distinguish “no prior document; provisional insertion was discarded” from “an intentionally committed empty document.” Test both immediate completion and completion after a provisional typing save, as well as deleting a previously committed last layer (which must still persist an empty document).

6. **P2 — Static full-screen compositions are invalidated on every countdown tick.** `Sources/Controllers/LockScreenController.swift:85` calls `renderPanels()` every second, which at line 199 reassigns the same scene to every scene view. `Sources/SceneRenderer.swift:94` unconditionally sets `needsDisplay`; each redraw traverses the whole scene, measures the text again, composites photos and opens transparency layers. This imposes continuous foreground drawing work for an unchanged lock image, contrary to the spec’s explicit static-rendering requirement (§15); the behavior is independent of whether the protected space is visible on this host. Keep the poll/order retry and legacy countdown refresh, but only invalidate a personal scene when new content arrives, the frame changes, or AppKit requires redisplay. Check that ticking an unchanged scene leaves its view clean and that an actual edit still invalidates it.

## Scope and evidence

The versioned scene, guarded asset access, shared renderer, snapshot history, UUID-based selection, startup recovery, nil-target Edit menu, and retained legacy controller are coherent Stage A building blocks. Existing tests and the root’s production smoke are useful evidence for picker replacement, photo dragging, focus-sensitive text Undo and restored scene data. No general pasteboard, app window, production store, display setup, elevated panel or lock was accessed during this review. The image probe used generated memory buffers only. Existing suites/builds were not rerun.

Visible external image paste and Finder drop (add and replace), physical display removal/reconnection, the eight-second actual panel and the new renderer on a protected lock screen remain unverified. The PNG probe is an import-validity finding, not evidence of native paste/drop routing. The coordinate issue follows from code and documented AppKit semantics, not an observed wrong-screen incident. Neither compilation nor prior legacy secure-lock evidence verifies the new renderer. Notes, timers, advanced transforms and a persisted display picker are outside this review.
