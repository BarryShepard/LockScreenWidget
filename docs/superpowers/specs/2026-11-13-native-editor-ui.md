# Нативный интерфейс редактора

Дата: 13 ноября 2026 года. Обновлено 14 ноября. Статус: пользователь поручил реализацию; первый этап окна и ориентиров выполняется по [плану](../plans/2026-11-14-native-editor-shell.md). Открытые вопросы ниже сохраняются до отдельного решения.

Документ уточняет [основную спецификацию](../../editor-spec.md) по текущему обсуждению. В согласованных ниже пунктах новые решения заменяют прежние: панель слоёв, кнопки Undo/Redo, отдельный редактор отсчёта, связанное переключение ориентиров, вставку инструментом в центр и ресайз стикера. Остальные ранее согласованные возможности сохраняются. Предложения и открытые вопросы не считаются утверждёнными требованиями.

## 1. Окно и нативные компоненты

Согласовано:

- Использовать нативные компоненты macOS: меню, поля, селекты, диалоги выбора файлов, палитру и календарь. Изображения служат референсами состава настроек и поведения; внешний вид контролов следует macOS.
- Панель слоёв оставить и сделать сворачиваемой. Сворачивание не меняет выделение, видимость объектов, группы и порядок элементов.
- Убрать кнопки отмены и повтора из интерфейса; команды доступны в меню «Правка» и по Cmd+Z / Cmd+Shift+Z.
- Убрать отдельный прежний редактор отсчёта из пользовательского интерфейса. Таймер остаётся элементом сцены.
- Правая панель зависит от выделения: нет выделения — фон; один элемент — его свойства.
- У всех элементов есть общая прозрачность.

Ориентиры часов и поля пароля скрываются независимо друг от друга, только в редакторе. При выключении ориентира часов он сразу скрывается. Подсказка с переходом в настройки экрана блокировки macOS открывается только по кнопке «?»; она поясняет, что настоящие системные часы отключаются там. Закрытие подсказки не возвращает ориентир. Настоящие системные элементы и отдельный элемент сцены «Часы» от этого переключателя не меняются.

Уточнение 14 ноября после проверки: подсказка отображается в нативном поповере у кнопки «?» рядом с ориентиром часов, не увеличивая панель и не сдвигая холст. Поповер открывается только по клику на нативную кнопку помощи «?»; переключение ориентира его не открывает. Повторный клик на «?» закрывает подсказку. Также она закрывается крестиком или кликом снаружи.

## 2. Добавление и контекстные меню

Выбор инструмента включает режим размещения. Следующий клик по холсту задаёт место нового элемента вместо автоматической вставки в центр. Список типов: текст, заметка/стикер, таймер, часы, картинка, фигуры.

После создания возврат к выделению, Escape отменяет размещение. Протягивание рамки для текста сохраняется по основной спецификации. В текущей реализации текст начинается в точке клика или в протянутой рамке; заметка, таймер, часы и фото центрируются в точке с сохранением прежних ограничений размеров. Диалог выбора картинки открывается после клика по холсту; отмена не создаёт слой.

### ПКМ по холсту

- Добавить → Текст, Заметка, Таймер, Часы, Картинка, Фигуры.
- Фигуры → Прямоугольник, Эллипс, Полигон, Звезда.
- Вставить сюда.

Согласовано пользователем 14 ноября: «Добавить» из контекстного меню создаёт объект сразу в точке ПКМ; правило следующего клика применяется к выбору инструмента вне холста.

### ПКМ по элементу

- Копировать.
- Вставить сюда.
- Вставить с заменой.
- На передний план.
- На задний план.
- Сгруппировать выделенное.
- Разгруппировать — для группы.
- Заблокировать / Разблокировать — по состоянию.

Реализовано: ПКМ по невыделенному незаблокированному объекту сначала выбирает его; ПКМ внутри текущего множественного выделения сохраняет весь набор. Неприменимые команды недоступны. «Вставить сюда» привязано к точке вызова меню, без неявной замены выбранного изображения.

Согласовано:

- «Вставить с заменой» уже работает с клавиатуры. Добавить вызов существующей команды из контекстного меню для целевого элемента; сохранить её текущие правила замены и поведение Cmd+V. Перед реализацией проверить существующий обработчик, не проектировать замену заново.

Уточнение пользователя 14 ноября: блокировка запрещает выбор курсором; через список слоёв заблокированный объект можно выбрать и менять его параметры. В строках слоёв показывается кликабельный замок, который блокирует/разблокирует слой. У группы замок действует на всех потомков, частичная блокировка обозначается отдельно. Курсорные hit/marquee и расширение групп не выбирают заблокированные листья. Если заблокированный слой уже выбран через список, его ПКМ предлагает разблокировку без нового выбора. Состояние сохраняется и поддерживает Undo/Redo.

Меню текущего этапа охватывает пять существующих типов. Фигуры и управление видимостью добавляются своими этапами; неработающие пункты в меню не показываются. Полный результат текущего этапа: [проверка](../../native-editor-placement-verification.md).

## 3. Фон при отсутствии выделения

Селект типа фона:

| Тип | Согласованные настройки |
| --- | --- |
| Сплошной цвет | Нативная палитра macOS и ввод HEX |
| Без фона | Прозрачная композиция поверх системного фона |
| Картинка | Выбор файла; заполнение экрана с сохранением пропорций и обрезкой вместо деформации |

Градиенты и паттерны отложены целиком. Ранее обсуждались линейный, радиальный, angular, diamond, mesh и настройки повторения паттерна; референсы сохранены для будущего этапа. GIF и видео для фона также не входят в текущий этап.

Открытые вопросы:

- При смене типа фона сохраняются ли предыдущие настройки каждого типа?

Согласовано пользователем 14 ноября: в первом этапе для картинки фона используется центральная обрезка.

Фон должен совпадать в редакторе и на панели блокировки для каждого из трёх доступных режимов.

## 4. Общие свойства элементов

По референсам для текста, изображения и стикера:

- Положение: выравнивание по горизонтали и вертикали, X/Y.
- Поворот: угол, поворот на 90°, отражение по горизонтали и вертикали. Доступность для стикера требует уточнения: в референсе эти контролы выключены.
- Размеры W/H — показаны у изображения и стикера.
- Видимость и прозрачность; общая прозрачность отличается от прозрачности отдельной заливки.
- Скругление: у изображения общий радиус и четыре отдельных угла; у стикера показан общий радиус.

Предлагается: положение и размеры в логических pt целевого экрана, угол в градусах, прозрачность в процентах. При множественном выделении показывать общие применимые настройки и смешанное значение там, где значения различаются. Базу выравнивания надо определить: холст или общее выделение.

Точные секции свойств группы, таймера и часов пока не заданы. Свойства фигур согласованы в разделе 8. Уже существующие настройки таймера и часов следует сохранить в общей структуре инспектора.

## 5. Текст

Согласовано по запросу и референсам:

- Шрифт: селект с поиском.
- Начертание: только реальные начертания выбранного шрифта.
- Размер, межстрочный интервал с режимом «Авто», межбуквенное расстояние.
- Горизонтальное и вертикальное выравнивание текста.
- Заливка: цвет, HEX, прозрачность цвета.
- Секция обводки.
- Общие положение и прозрачность элемента.

Базовое форматирование текста входит в текущий объём: жирный, курсив, подчёркивание, зачёркивание, маркированный и нумерованный списки. Для Markdown используются `**жирный**`, `*курсив*`, `~~зачёркнутый~~`, `- пункт` и `1. пункт`. Подчёркивание — отдельная возможность форматирования: стандартный Markdown не имеет общепринятого синтаксиса для него; `_текст_` означает курсив.

Предложение, не утверждено: добавить ссылки как ещё одну простую возможность. Заголовки, таблицы, изображения, блоки кода и другие расширения пока не входят в согласованный набор.

Согласовано пользователем 14 ноября: исходник Markdown виден при вводе, форматированный результат отображается вне ввода; подчёркивание включается отдельной командой.

Нужно определить:

- Представление подчёркивания в сохранённых данных и его поведение при правке исходника. Не включать исполнение произвольного HTML ради подчёркивания.
- Приоритет Markdown и настроек инспектора, формат копирования и вставки.
- Обводка обводит буквы или рамку блока? Нужны цвет, толщина, положение обводки?
- Поведение при смене шрифта, у которого нет прежнего начертания, и при отсутствии шрифта после переноса документа.

## 6. Изображение

- Общая секция положения.
- Размеры W/H.
- Видимость, прозрачность.
- Общий радиус и радиусы четырёх углов.
- Существующая неразрушающая обрезка и замена исходника сохраняются. Контекстная вставка с заменой использует уже работающую команду.

Предлагается добавить переключатель сохранения пропорций при вводе W/H. Нужны правила связи общего радиуса с отдельными углами; рекомендация: общий ввод меняет все четыре, индивидуальный — только выбранный угол.

## 7. Стикер (заметка)

Вернуть поведение, похожее на FigJam:

- Горизонтальное растягивание меняет ширину без масштабирования текста.
- Ширина переключается строго между одинарным и двойным форматом. Промежуточные значения ширины не фиксируются; масштаб всего стикера задаётся отдельно от формата.
- Растягивание вверх или вниз масштабирует весь стикер вместе с текстом.
- Угловые ручки также масштабируют весь стикер вместе с текстом и сохраняют выбранный одинарный/двойной формат.
- В инспекторе — положение, размеры, видимость, прозрачность, общий радиус и заливка.

Это заменяет прежнее правило, при котором все края и углы стикера меняют только бокс без масштабирования текста.

Нужно уточнить:

- Порог переключения ширины при горизонтальном жесте и поведение Shift/Option.
- W/H редактируемые или информационные, как на референсе с неактивными полями?
- Может ли текст увеличивать высоту, как обрабатывается переполнение?
- Нужна ли подпись автора, показанная на референсе? Пока она не считается требованием.

## 8. Фигуры

Добавить прямоугольник, эллипс, полигон и звезду как самостоятельные элементы сцены.

Согласованный набор свойств:

- Общие положение, размеры, поворот, отражение, видимость и прозрачность.
- Заливка и обводка.
- Прямоугольник: скругление.
- Полигон: число сторон.
- Звезда: число лучей и соотношение внутреннего/внешнего радиуса.

Нужно определить начальные параметры и создание кликом/протягиванием. Линии и стрелки пока не запрошены.

## 9. Поля и клавиатура

Согласовано:

- В числовом поле ↑ увеличивает значение, ↓ уменьшает.
- Поля дат открывают календарь.
- Выбор шрифта поддерживает поиск; список начертаний зависит от семейства.

Предлагается:

- Шаг зависит от величины: 1 pt, 1°, 1%; Shift увеличивает шаг в десять раз. Дробный ввод сохраняется.
- Значение ограничивается допустимым диапазоном свойства. Ошибка ввода не сбрасывает последнее корректное значение.
- Стрелки в активном поле меняют поле, а не положение элемента на холсте.
- Enter подтверждает ввод; Escape отменяет текущий неподтверждённый ввод. Автоповтор стрелок объединяется в одно действие Undo.
- Нативный календарь дополняется выбором времени и часового пояса там, где они нужны таймеру; существующие параметры таймера сохраняются.

## 10. Сохранение и совместимость

Предлагаемые обязательные условия реализации:

- Старые сцены открываются без потери объектов, групп, трансформаций и оформления; отсутствие новых полей имеет совместимые значения по умолчанию.
- Фоны, фигуры, отдельные радиусы и блокировка сохраняются и восстанавливаются. Файлы фона копируются в хранилище сцены, как обычные изображения.
- Все изменения документа поддерживают Undo/Redo; один жест — одно действие.
- Удаление входа в старый редактор не удаляет автоматически его данные. Нужен сценарий переноса прежнего отсчёта, если пользователь ещё не создал сцену.
- Редактор и экран блокировки используют одинаковую геометрию и оформление.
- Ориентиры не становятся элементами сцены и не выводятся поверх системного входа.

## 11. Проверка результата

После утверждения открытых решений проверить:

1. Панель слоёв сворачивается и разворачивается без изменения сцены и выделения. Нет кнопок Undo/Redo и входа в прежний редактор; команды «Правки» и хоткеи работают с учётом фокуса.
2. Каждый инструмент создаёт элемент в выбранном месте; отмена размещения не создаёт объект.
3. Контекстные меню различают пустой холст, объект, множественное выделение, группу и заблокированный объект.
4. Без выделения доступны все типы фона; смена фона отменяется, сохраняется и совпадает с показом на блокировке.
5. Инспекторы текста, изображения и стикера соответствуют согласованным полям. Прозрачность работает у всех типов.
6. Числовые стрелки не двигают объект, календарь выбирает дату, поиск шрифта и список начертаний работают.
7. Стикер переключается строго между одинарной и двойной шириной без изменения кегля; вертикальные и угловые ручки масштабируют его вместе с содержимым.
8. Все четыре фигуры создаются, редактируются, копируются и сохраняются.
9. Ориентиры часов и пароля переключаются независимо. Выключение часов сразу скрывает ориентир и показывает уведомление с работающей кнопкой настроек; закрытие уведомления не возвращает ориентир.
10. Старый документ открывается, после перезапуска новые свойства восстановлены, реальная блокировка не нарушает системный ввод.

11. Жирный, курсив, подчёркивание, зачёркивание и оба вида списков корректно редактируются, сохраняются, копируются и отображаются в редакторе и на панели блокировки. Способ ввода уточняется до реализации.
